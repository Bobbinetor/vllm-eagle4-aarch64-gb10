# vLLM 0.32.0rc1.dev283+eagle.3 — aarch64 / DGX Spark (GB10, sm_121)

Prebuilt `linux_aarch64` wheel of the EAGLE-4-patched vLLM fork, for NVIDIA DGX
Spark / GB10 (compute capability 12.1), Python 3.12, CUDA 13.

The official EAGLE-4 wheel index and container are **x86_64-only**. This is the
arm64 build of the same fork, with the 10-hook audit, the exact pins, and the
measured numbers.

## Install

```bash
# 1. Clone the repo (scripts + recipe), then download the wheel into it
git clone https://github.com/Bobbinetor/vllm-eagle4-aarch64-gb10.git
cd vllm-eagle4-aarch64-gb10
gh release download v0.1.0 --pattern '*.whl' --pattern 'SHA256SUMS'

# 2. Verify (the manifest also covers the recipe files, hence --ignore-missing)
sha256sum -c --ignore-missing SHA256SUMS
python3 scripts/audit_hooks.py vllm-*.whl     # expect: 10/10 hooks present, RESULT: PASS

# 3. Build and run (the wheel is already compiled)
docker build -f docker/Dockerfile.eagle -t vllm-eagle:gb10 .
./scripts/serve.sh
```

The Dockerfile fails the build if `eagle-harness-check` does not pass, so a
broken hook surface cannot be served silently.

## Measured numbers

Single DGX Spark (GB10), Qwen3.8-27B NVFP4 + EAGLE-4 draft, 64K context,
concurrency 1, temperature 0, 3 requests per preset:

| Configuration | Agentic tok/s | Echo tok/s | TTFT (agentic) |
|---|---:|---:|---:|
| Base (no speculative decoding) | 12.17 | 12.13 | 141 ms |
| DFlash2 | 29.10 | 29.22 | 138 ms |
| **EAGLE-4** | **35.17** | **53.05** | 239 ms |

EAGLE-4 is a **decode-throughput** win (≈2.9× over base on the agentic prompt),
not a latency win: TTFT is higher than DFlash2. The echo prompt is synthetic; do
not read 53 tok/s as a general number.

## Compatibility

- **Works on:** DGX Spark / GB10, sm_121, Ubuntu 24.04.x DGX OS, driver
  580.159.03 (CUDA 13.0), Python 3.12, `eagle-harness` 0.1.4.
- **Does not work on:** x86_64 (use the official wheel), GH200 / Grace Hopper /
  Jetson or other non-sm_121 ARM GPUs, Python 3.11/3.13, quantized KV cache
  (`--kv-cache-dtype fp8`).
- **Not tested:** a second machine, concurrency > 1, long-running stability,
  other target models or drafts, power/thermal behavior.

## What is verified

- Wheel checksum, tag, and size.
- Static audit of all 10 hooks `eagle-harness` 0.1.4 resolves.
- `eagle-harness-check` at runtime.
- `/health`, `/v1/models`, chat, tool calls, streaming, 64K context smoke case.
- Single-stream throughput and TTFT for base, DFlash2, and EAGLE-4.

## Known deltas

- The wheel reports `+eagle.3`. Upstream's current reference build is `+eagle.5`
  (`main 074c83a09a` + hooks and fixes). The hook contract is the same;
  `eagle-harness` 0.1.4 accepts `+eagle.3`. The rebuild path is in
  [`docs/it/EAGLE4-BUILD.md`](https://github.com/Bobbinetor/vllm-eagle4-aarch64-gb10/blob/main/docs/it/EAGLE4-BUILD.md).
- Built against torch 2.13.0; the tested image runs torch 2.14.0+cu130 because
  `pip install "eagle-harness[vllm]"` resolves it. This is the tested pair.
- `flashinfer_cutedsl` is not used: there is no `flashinfer-python` arm64 wheel.
  The default linear backend is used.
